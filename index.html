How many copies of an AI model until one fixes the bug?

A small calculator, and the one idea behind it: at least one success means not every attempt fails.

Point a language model at a real bug and it will often get it wrong. Then comes the obvious question: if one attempt only works some of the time, how many attempts should I run?

Retrying, adding context and rewording the prompt all keep the same model and spend more effort while it answers. That effort is called inference time. The simplest way to spend it is to run several independent copies at once and stop the moment one of them works. I built this calculator to turn “one copy fixes this about 16% of the time” into a concrete number of copies, with every step visible so you can check it yourself.

The idea in one line

Getting at least one fix is the opposite of every copy failing. If one copy succeeds with probability p, and the copies don’t influence each other, the chance that all n of them fail is (1 − p) multiplied by itself n times. Take that away from 1 and you have the answer.

P(at least one fix) = 1 − (1 − p)n n = ⌈ ln(1 − target) / ln(1 − p) ⌉

The second line solves the first for n. It is rounded up because you can only run whole copies, and you need to at least reach your target.

The numbers behind it

The default p of 0.159 is the one-try rate of DeepSeek-Coder-V2-Instruct on real GitHub bugs (SWE-bench Lite), reported in Brown et al., “Large Language Monkeys” (2024). With it, the page shows the full derivation in events, the algebra, a table of copies against failure chance, and a graph with your target drawn as a line.

What surprised me

  • “One in six, so six copies” is wrong. At 0.159, six copies give about 64.6%, not 100%.
  • Each extra copy helps less than the one before, and no number of copies ever reaches 100%.
  • A better model pays off quickly. For a 99.9% target you need 40 copies at 0.159 but only 20 at 0.300.

Where the model breaks down

  • Independence is an assumption. If the model keeps making the same mistake, extra copies are not fresh tries, and real results will be worse than the formula says.
  • One p for every bug is a simplification. Real problems vary in difficulty, so real curves are usually shallower than this idealized one.
  • You still need a way to pick the winner. The calculator tells you when a correct answer probably exists among the copies, not which one it is. Tests or another verifier turn that into an actual fix.
  • Cost grows with the number of copies. It counts attempts, not dollars or waiting time.
